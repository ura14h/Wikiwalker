## 2. 目的と設計原則

Wikiwalkerは、Wikipediaの記事を「恒星」、記事に属する関連記事のまとまりを「惑星」として3D空間へ恒星系のように配置し、知識のつながりを散策するグラフィカルブラウザーである。

設計原則は次のとおりとする。

1. 検索、選択、探索、履歴移動を単一画面内で完結させる。
2. 意味的に近い記事をすばやく提示し、その背後で実際の出リンクと被リンクの標本を収集する。
3. 大量のリンク先を記事星として並べず、共有カテゴリに基づく惑星へ決定論的に集約する。出リンクと被リンクは同じ惑星へ混ぜ、方向で表示を分けない。
4. 通信中もローカルのグラフ操作と既存データの閲覧を禁止しない。
5. Wikimediaのレート制限、Robot policy、帰属表示およびライセンス条件を守る。
6. 単一HTMLを直接開いて利用でき、ビルドやローカルサーバーを要求しない。
7. 主要操作をキーボードと狭い画面からも利用できるようにする。
8. 初期画面では視線の先に最初の操作（検索）を置き、最初の記事が現れるまでの待ち時間を演出で覆う。

## 3. 用語

| 用語 | 定義 |
| --- | --- |
| 記事星（恒星） | Wikipedia名前空間0の記事に対応する暖色の球形ノード。恒星系の中心 |
| 類似記事星 | CirrusSearch `morelike:` の上位結果。起点記事との意味的類似を表す恒星 |
| 惑星 | 同じカテゴリを共有する複数の関連記事（出リンク先・被リンク元）を集約した寒色の球形ノード。親となる恒星の軌道に並ぶ |
| その他の惑星 | 有効な共有カテゴリへまとめられなかった関連記事の集合。環のある寒色の球で、画面上の名称は「その他」 |
| 選択記事 | 現在カメラの注視対象となり、詳細パネルへ内容を表示している記事 |
| 探索run | ひとつの選択記事を起点に、類似記事、出リンク、被リンク標本を収集してグラフへ反映する一連の非同期処理 |
| 意味的類似辺 | `morelike:` 検索結果と起点記事の関係。実リンクの存在は保証しない |
| 出リンク | 選択記事の本文から別記事へのリンク。選択記事が説明に使っているもの |
| 被リンク | 別記事の本文から選択記事へのリンク。選択記事を使っている側（応用、具体例、関係人物）。全数ではなく無作為標本を扱う |
| 初期画面 | 記事未選択の状態。タイトル、案内、検索欄を中央に置き、背景に星間航行を描く |

## 4. 対象範囲

### 4.1 提供機能

- ブラウザー設定に基づくWikipedia言語版の自動選択
- 言語名またはコードによる言語版の手動選択
- インクリメンタル記事検索
- 記事概要、カテゴリ、収集の集計および原文リンクの表示
- 類似記事星の高速表示
- 全出リンクと被リンク標本のバックグラウンド取得とカテゴリ惑星への集約
- 恒星、惑星、その他の惑星の選択と展開
- 選択記事と開いた惑星の履歴の「戻る」「進む」移動
- 初期画面の中央検索欄と、最初の記事選択時の星間航行演出
- 回転、平行移動、ズームが可能な3Dグラフ
- 言語切替時の言語間リンクによる同一記事への移動
- 通信混雑、待機、失敗の通知
- Wikipediaの帰属、ライセンスおよび商標表示

### 4.2 対象外

- Wikipedia記事の編集
- Wikipediaへのログインまたは認証
- 記事の表・画像・脚注リンクの再現（本文はプレーンな限定HTMLで読む）
- 複数言語版を同じグラフへ同時配置する処理
- グラフの永続保存、共有、画像出力
- オフラインの記事検索および記事本文取得
- サーバー側コンポーネント、データベース、プロキシ

## 6. 画面仕様

### 6.1 全体構成

```text
┌──────────────────────────────────────────────────────────────┐
│ Wikiwalker   [JA] [記事を検索…                 ]  [‹] 1/3 [›] │
│                                                              │
│            ○ 類似記事                         ◎ 惑星         │
│                 ╲                             ╱               │
│                   ● 選択記事 ─────────────── ○               │
│                 ╱                                            │
│            ◌ その他                    ┌───────────────────┐ │
│                                        │ 記事詳細・進捗    │ │
│ [記事星 / 惑星]                        └───────────────────┘ │
│ 出典・CC BY-SA・商標表示       左回転 / 右・Shift平行移動   │
└──────────────────────────────────────────────────────────────┘
```

3Dグラフを画面全面へ表示し、検索、履歴、詳細、凡例、操作案内、状態および権利表示を上層へ固定配置する。凡例と操作案内は左上に縦に並ぶ同じ様式の小さな箱（HUD）で、探索中だけ見える。操作案内は「回転／移動／拡大／検索」の2列で、入力はマウスの絵記号（押すボタンやホイールだけをアクセント色で塗った小さなSVG）とキーキャップで示す（回転: 左ボタンでドラッグ、移動: 右ボタンでドラッグ または ⇧＋左ボタン、拡大: ホイール、検索: `/` キー）。ホバーのない端末と幅840px以下では出さない（画面下中央に置くと視野の中央下を塞ぎ、権利表示とも競合する）。

### 6.2 初期画面

記事未選択時は次の構成にする。

```text
┌──────────────────────────────────────────────────────────────┐
│                  ・   ＼   ｜   ／   ・    （星間航行）        │
│                     ATLAS OF KNOWLEDGE                       │
│                      知識の宇宙を、                          │
│                        歩く。                                │
│           ひとつの記事から、思いがけない隣の世界へ。         │
│              [JA] [記事を検索して、歩きはじめる     ]        │
│              ／      ｜      ＼                              │
└──────────────────────────────────────────────────────────────┘
```

- 検索欄はヘッダーではなく案内文の直下に置く。視線が集まるタイトルの真下に最初の操作を置き、上端へ視線を移す必要をなくす。言語ボタンは検索欄内にあるため初期画面でも言語を選べる。
- ブランド、履歴ボタン、権利表示および操作案内は初期画面では表示しない。記事の内容を表示していない間は帰属表示の義務が生じないため、最初の記事星と同時にフェードインさせる。
- 背景には中心から星が流れてくる星間航行（2D canvas）を描く。星は奥行きを持ち、手前ほど白く太い尾を引く。初期画面の間だけ描画し、探索中は停止する。流し始める前に、重い準備（惑星テクスチャの生成と恒星・惑星・銀河のシェーダーのコンパイル、合計1秒弱）を済ませ、流れている最中や最初の記事星の出現時に描画が止まらないようにする。
- 案内の各要素は表示時に下から浮き上がり、検索欄は輪郭のない広い光がゆっくり（5.2秒周期）呼吸して入力を促す。輪や枠を点滅させると星の滑らかな流れに対してカーソルのように見えるので、光の `opacity` だけを動かす。ポインター端末では検索欄へ自動的にフォーカスする。タッチ端末ではソフトキーボードを勝手に出さない。
- タイトルの行末の全角句読点は右側の空きを詰め、行の見た目の中心を揃える。

入力が始まったら案内全体を持ち上げ、検索欄をヘッダーの定位置と同じ高さに合わせて候補リストの場所を空ける。検索欄だけが動くのではなく視点が平行移動したように見せるため、タイトルや案内文は消さずに一緒に動かして上端で見切れさせ、星間航行の流れの中心も同じ向きに視差（持ち上げ量の45%、550ms の ease-out）で動かす。候補を選んでワープに入るときは、流れの中心を記事星が現れる画面中央へ戻す。検索欄のDOMは動かさず、IME変換中は `compositionend` まで持ち上げを待つ。これはOSのIME候補ウィンドウが入力欄の移動へ追従しないためである。入力を全部消しても中央へは戻さない（IME候補ウィンドウが取り残されるため）。中央へ戻るのは初期画面に入り直すときだけである。

候補を選んだ瞬間に次を同時に始める。

1. 検索欄をヘッダーへ移し、移動前後の位置と幅をつないで飛ばす（FLIP、720ms）。持ち上げ済みなら幅の差だけを補間する。着地時に検索欄から光の輪が一度広がる。
2. 案内文は検索欄と同じ上向きに流れながら消える。
3. 星間航行はワープに入り、ease-in（550ms、3乗）で加速して尾が伸びたまま散り続ける。
4. 記事星は配置するが、拡大率0で隠しておく。

記事本文が届いた（または取得を諦めた）時点で、ワープ開始から最低700ms経過していることを確認してから星々を暗闇へ溶かす（800ms）。溶けている間は星の速度も ease-out（3乗）で落とし、尾が縮みながら消える。同時に記事星を遠くの点（拡大率0.06）として現し、同じ ease-out で近づいて止める（900ms）。ワープの勢いを記事星の接近が引き継ぐので、一連の流れが一つの減速として繋がる。本文の到着が遅いほどワープが長く続き、待ち時間をスピナーではなく演出で覆う。

記事星が現れ切ったら、利用者が自分で開くときと同じ動きで着陸シートを開く。まず帯（6.7）が右下に現れ、600ms おいて帯がシートへ伸び（360ms の ease-in-out）、注視点の寄せ（6.6）もそれに同期して動く。シートが右から丸ごと現れる独自の入場にすると開閉の動きの語彙が増え、到着後の視線が迷う。タッチ端末では帯のまま止まる。

言語変更などでグラフを初期化した場合は初期画面へ戻す。散策中から戻る場合は検索欄がヘッダーから中央へ降りてくる。`prefers-reduced-motion` が有効な場合は星間航行を描かず、移動は即時に切り替える。

### 6.3 ヘッダー

| 要素 | 仕様 |
| --- | --- |
| ブランド | `Wikiwalker` と短い副題を表示する。狭い画面では省略可能。クリックすると全景（全ノードが収まる視点）と直前の視点をトグルする隠し機能を持つ。全景中はノードを選び直すまで自動フレーミングを止め、選び直すと全景は解除される |
| 言語ボタン | 現在の言語コードを大文字で表示し、言語ダイアログを開く |
| 検索入力 | 入力をデバウンスしてWikipediaを検索する。`/` キーでもフォーカスできる |
| 消去ボタン | 入力文字と候補を消去し、入力へフォーカスを戻す |
| 戻る / 進む | 選択履歴を前後移動する。ツールチップとアクセシブル名は「戻る」「進む」。移動不能な側は無効にする |
| 履歴位置 | `現在位置 / 履歴数` を表示する |

### 6.4 検索候補

- 最大8件のタイトルと抜粋を表示する。
- APIの抜粋からHTMLを除去してプレーンテキスト化し、現在の検索語と一致する箇所だけをテキストノードと安全な `mark` 要素に分けて強調する。
- 上下キーで選択行を移動し、Enterで決定、Escapeで閉じる。
- IME変換中のキーイベントは検索候補操作へ使用しない。
- 選択行が候補領域外へ出た場合は自動スクロールする。
- マウスのクリックで候補を直接決定できる。ホバーは枠線だけの視覚的な反応にとどめ、Enterで決定される仮選択（塗り、`aria-activedescendant`）はキーボードでしか動かさない。初期画面の持ち上げで候補リストが静止したポインターの下に来ても、仮選択が飛ばないようにするためである。
- 入力変更時は未完了の検索を中止し、古い検索結果を表示しない。
- グラフ上の記事選択や履歴移動によって検索欄の値を記事タイトルへ更新する場合は、未完了の検索と保存済み候補を破棄する。その後に入力欄へフォーカスしても、以前の入力に対応する候補を再表示しない。
- 候補リストは `listbox`、各候補は `option` として公開する。

### 6.5 言語選択

- 言語名、現地語名またはコードで絞り込めるモーダルダイアログとする。
- Site matrix取得前も主要言語の暫定一覧を直ちに表示できるようにする。
- Site matrixはバックグラウンドで取得し、成功後に全言語一覧へ置き換える。
- 取得済み一覧を取得日時とともに7日間 `localStorage` へキャッシュする。
- 選択言語コードを保存し、次回起動時の優先候補にする。
- 記事選択中の言語変更では `langlinks` から同一記事の移動先を探す。存在すれば移動先記事から再出発し、なければ初期画面へ戻して通知する。

### 6.6 3Dグラフ

| 操作 | 結果 |
| --- | --- |
| 左ドラッグ | グラフを回転する |
| 右ドラッグ、またはShift + 左ドラッグ | グラフを平行移動する |
| ホイールまたはトラックパッド | ズームする |
| 記事星をクリック | 記事を選択し、詳細表示と未完了の探索を開始する |
| 惑星をクリック | 惑星詳細を表示し、内包記事の一部を記事星として展開する |
| 惑星詳細の記事をクリック | 対象記事を選択する |

選択ノードは位置を固定し、白熱色、大きい半径、強いコロナおよび拡大ラベルで強調する。選択ラベルはズームアウト時にも基準距離での見かけの大きさを下回らないよう、画面への投影深度に応じて拡大する。すでに規定以上に大きく見えるラベルは拡大しない。選択ノードへ直接接続されたノードは、距離による霞を残しながら不透明度、発光およびラベル背景を少し明るくし、現在の探索範囲を判別できるようにする。

ノードの見た目は恒星系の比喩に従う。

| ノード | 形 | 色 | 大きさ |
| --- | --- | --- | --- |
| 恒星（記事） | 球。シェーダーで対流のセルと粒状斑を描き、コロナを重ねる | 温白。探索深度で淡黄〜淡橙を巡回し、選択中は白熱色。暗部は橙へ寄せる | 半径4.6（探索済み6.2、選択中8.2） |
| 惑星（カテゴリ） | 球。手続きテクスチャ（木星風・火星風・地球風） | 寒色（青・青灰）。地球風だけ海と大陸の色 | 半径3。ラベルも恒星より小さい |
| 環のある惑星（その他） | 球＋平らな環（土星風） | 寒色（青緑） | 半径3、環の直径は半径の4.6倍 |
| 銀河（遠くの訪れた恒星系） | 渦巻きの腕に沿って散らした点群＋中心の淡い輝き | 中心は青みの灰、腕は青灰・青緑・薄紫のいずれか（記事IDで決定論的） | 半径18＋畳んだ惑星1個あたり1.6（上限40）。ラベルは記事の見出し |

恒星の暖色は温白（`#ffe9c4` 系）とし、赤みは寒色の惑星・銀河との対比に必要な分に留める。宇宙で最も明るく暖かい光点が常に恒星（とりわけ選択中の記事）になるようにする。

辺は恒星–恒星（`similar`、展開した`member`）を暖色で、恒星–惑星（`cluster`）を細く淡い寒色で描き、所属関係を線として残す。惑星を注目しているときは、どの恒星を選択中でも、その惑星と親の恒星を結ぶ線を白く太くし、親の恒星を少し明るく（不透明度1、発光とラベル背景を強める）して所属先を示す。

配置は力学レイアウトに軌道力を加えて恒星系を作る。

- 惑星は親の恒星を囲む球殻（半径44、8個を超えると面積に応じて広がる）に、フィボナッチ球で等間隔に散らばるスロットへ引き寄せられる。軌道面を持たない立体的な配置なので、どの向きから見ても一列に重ならない。球の向きは恒星IDから決定論的に決め、「その他」は最後の席に座る。
- 恒星–惑星の辺の長さは軌道半径、恒星–恒星の辺の長さは135とし、恒星同士の距離が恒星–惑星の距離より常に長くなるようにする。惑星の反発は弱く（間隔は軌道が作る）、恒星の反発は強い。
- 惑星は親の位置から出現して軌道へ滑り出す。

ノードをホバーしたときは別置きのツールチップを表示せず、対象ノードと既存のラベルスプライトを明るくする。ラベルは選択ラベル相当の見かけの大きさを下限として滑らかに拡大し、遠方ではカメラとの距離に応じて補正する。ホバーを外したときは元の大きさへ戻す。`prefers-reduced-motion` が有効な場合は拡縮を即時反映する。

各ノードには見た目より少し大きい透明な当たり領域を持たせる。ノード選択はポインター押下から解放までの移動量が6px以内の場合だけクリックとして扱い、解放直後のカメラ位置でraycastをやり直す。これにより視点移動後の古いhover判定や通常クリックの微小な手ぶれによる不発を避け、明確なドラッグ終了時にはノードを選択しない。

背景は装飾用の点群やダミーノードを置かない無地の空間とし、初期表示では記事・惑星ノードを1件も描画しない。選択記事から遠いノードは距離に応じて霞ませる。新しいノードは親ノードの位置から短い間隔で1件ずつ追加する。

#### 恒星の表面とコロナ

恒星は `ShaderMaterial` で描く。表面は3Dノイズを2層（大きな対流のセルと、ridgedにした細かい粒状斑）重ね、時刻で流す。縁は周辺減光で少し暗く橙に。色はpaletteの色を基準に、明部は白へ6割、暗部は橙（`#e8a060`）へ半分寄せる。強調の段階（選択・注目・ホバー・隣接・通常）は明るさの倍率（.92〜1.05）に写し、白飛びさせない。

コロナは恒星の6.5倍幅の板を頂点シェーダーでビルボード化したもので、球の縁に張り付いた揺らぐ帯、低周波ノイズの山だけ拾って2〜3か所が大きく盛り上がってゆっくり戻るプロミネンス、広い裾の光からなる。強さは選択1、注目.9、ホバー.7、通常.5。コロナと環はクリック判定の対象にしない。恒星は0.03 rad/s（1周3.5分）で自転し、コロナの縁の模様も同じ向きに回る。

#### 惑星のテクスチャ

惑星は正距円筒図の手続きテクスチャを貼る。種類は収容する記事数とノードIDのハッシュで決定論的に選び、同じカテゴリは何度出ても同じ模様になる。

| 種類 | 条件 | 見た目 |
| --- | --- | --- |
| 土星風 | その他 | 淡い青緑の帯（30〜36本）と平らな環（放射方向の濃淡とカッシーニ風の隙間） |
| 地球風 | 収容 ≥ `earthMin`（5）かつ ハッシュが `earthChance`（40）分の1 | 海と大陸（ノイズの閾値）、緯度と乾燥度で植生→砂漠→雪、雲 |
| 木星風 | 収容 ≥ `jupiterMin`（20） | 青のパステルの帯（24〜34本）。色差はごく薄い |
| 火星風 | それ未満 | 青灰の砂と岩、クレーター、極冠（暖色は恒星の印なので赤にしない） |

帯は赤道で広く高緯度ほど細く（帯番号の変化率: 赤道0.4、極2.2）、|緯度| > 55%で帯のコントラストが平均色へ落ち、極域は斑点状の渦になる。ノイズは正距円筒の(u, v)を球面上の点に戻してから引くので、継ぎ目も極の収束もない。テクスチャは種類ごとに数枚（木星風3、火星風2、地球風1、土星風2、環2）を起動後の空き時間に1枚ずつ生成して全惑星で共有し、間に合わなければその場で生成する。影の側でも模様が見えるよう、テクスチャ自体を弱く発光（`emissiveMap`、.25）させ、強調の段階で少し上げる。惑星は自転軸を少し傾け、0.04〜0.08 rad/s（1周1.3〜2.6分）で自転する。

#### 星の動きの制御

恒星の対流とコロナ、恒星・惑星・銀河の自転は1つの描画ループで進める。力学シミュレーションが止まると描画tickが来ないため自前のループで回し、動かすのはカメラから `motionRange`（700）以内にあるものだけとする（遠景では分からない）。近くに動くものが無ければループも止め、カメラの移動や星の追加で再開する。自転の角度はノードに持ち、描画物を作り直しても位相を引き継ぐ。時刻は絶対時刻なので作り直しで跳ねない。`prefers-reduced-motion` が有効なら動かさない。シェーダーの費用は画面上の面積に比例するので、遠くの小さな恒星は自然に安くなる。

#### 注目からのホップ距離による段階

数十の記事を歩いた後も「今いる星系」だけが浮かぶよう、注目ノード（開いている惑星があればそれ、なければ選択中の記事）からグラフの辺を向きなしに辿ったホップ距離で見え方を3段階に分ける。ホップ距離は辺やノード、注目が変わるたびに幅優先探索で取り直す。

| 段階 | 既定 | 効果 |
| --- | --- | --- |
| 減光 | `hopOpacity: [1, 1, .7, .45]` | 添字＝ホップ数の倍率を距離による霞に掛ける（末尾はそれ以遠すべて）。発光も同じ倍率で落とす |
| ラベル | `labelHops: 2` | これ以遠のノードはラベルを出さない。ただし強調中（選択・注目・ホバー・親）と訪れた記事星は常に出す。ホバーすれば出る |
| 畳み | `collapseHops: 3` | これ以遠の訪れた恒星系は、惑星ごと1つの銀河に畳む。近づけば恒星系に戻る |

ホップ数の落とし所は歩きながら決める。実行中は `wikiwalker.graph.cfg.collapseHops = 2; wikiwalker.graph.syncSystems()` のように変えて試せる。

#### 銀河（恒星系の畳み）

訪れた記事星（一度でも選択した記事。収集が中断されたものも含む）が注目から `collapseHops` 以遠になったとき、その恒星系を1つの銀河ノードに畳む。

- 畳む対象は、恒星の惑星（カテゴリ・その他）と、恒星や惑星から生えた未訪問の末端の記事星（この恒星系にしか繋がっていないもの）。訪れた記事星は自分の恒星系として残り、必要なら自分も銀河になる。
- 畳んだノードと辺はグラフから外して恒星に預ける（`__system`）。預けたノードの向こう側に残るノード（惑星から訪れた記事星など）は銀河から直接の仮の辺で繋ぎ、グラフが千切れて漂わないようにする。
- 恒星は銀河として描き直す。形（腕の本数2〜3、ねじれ、傾き、腕の色）は記事IDのハッシュから決定論的に決め、同じ記事は何度畳んでも同じ形になる。点群は加算合成の柔らかい点で、注目する星系より沈むよう点は少なく（700）色は霞ませ、霧とホップの減光を受けるが下限（点 .3、輝き .18、ラベル .5）より薄くはしない。
- 銀河はゆっくり自転する（0.1 rad/s、1周に約1分）。動きの制御は「星の動きの制御」と同じ。
- 銀河のクリックは記事の選択であり、選択されると恒星系に戻る。履歴で戻る、着陸シートの記事一覧から選ぶなど、畳まれた中のノードが必要になったときも、その恒星系を開いて取り出す（`recall`）。戻したノードは銀河の位置から出て軌道へ滑り出す。
- 銀河への切り替えとその逆は、選択・注目の変更時と、ノード追加が一段落したときに判定する。

関連ノードの追加が一段落するたびにカメラ調整をデバウンスし、現在の選択ノードと、その選択ノードへ直接接続された全隣接ノード（新規・既存とも）の85%が画面内へ収まる距離まで自動的にズームアウトする。

- 各ノードに必要なカメラ距離を昇順に並べ、上位85%（`frameCoverage`）が収まる距離を採用する。最も遠い少数には合わせないので、既存ノード同士が結び付いて遠くの隣接ノードが増えても引きずられない。
- 必要距離は最大3D半径ではなく、各ノードをカメラの水平軸・垂直軸へ投影した実寸から求める。
- 検索バー、権利表示が覆う上下の帯を実測し、そのうち大きいほうを両側から除いた帯を有効な視野とみなす。ノードがUIの下に隠れない。
- 現在の視線を中心とした円錐内の候補方向（6°刻み、方位12分割）を評価し、評価値が12%以上下がる向きがあればそちらへ回りながら動く。評価値は必要距離に、視線軸の近く（26以内）にある隣接ノードの重み付き個数による割増（1個あたり20%）と回転角の割増を掛けたもので、選択ノードの手前や奥に惑星が重なって見える向きを避ける。回転は1回の選択につき合計24°まで（人間の有効視野約48°の半分）、平均角速度10°/s以下で、角度に応じて移動時間を延ばす。画面の傾き（カメラのup）は変えない。ズームが不要でも重なりがあれば回転だけの移動を行うが、重なりがなければ回転だけの移動はしない。
- 視覚誘発性動揺病（VIMS）は数分間の持続回転で14°/s以上から報告され、その主因である自己運動感（ベクション）の発生には外部ディスプレイで平均8〜9秒かかる。1回2秒台の小さな回転はこの手前に収まる。ただし3D力学レイアウトは隣接ノードをほぼ等方的に散らすため、回転で縮む必要距離は数%〜1割程度である。

追加中の各ノードごとにカメラを動かして画面を揺らさず、利用者が手動操作している間は自動調整を割り込ませない。自動調整後に力学レイアウトが収束して必要距離が短くなった場合に限り、利用者がその後手動操作していなければ一度だけ適正距離へ寄せ直す。`prefers-reduced-motion` が有効な場合はアニメーションせず即時調整する。

辺は由来を内部データに保持する。

| 辺種別 | 由来 | 表示上の意味 |
| --- | --- | --- |
| `similar` | `morelike:` | 意味的に近い候補 |
| `cluster` | カテゴリ集約 | 起点記事と集約惑星の関係 |
| `member` | 惑星展開、履歴からの移動 | 惑星と内包記事、または移動元と移動先の関係 |

辺は無向として扱い、同じ2ノード間には1本だけ持つ。`generator=links` で得た出リンクと `linksto:` で得た被リンクは惑星の構成材料として保持し、直接辺として描画しない。リンクの方向は辺の見た目に反映しない。

### 6.7 覗きカードと着陸シート

記事の情報は利用者の意思の強さに合わせて3段階で出す。

| 行為 | 意思 | 表示 |
| --- | --- | --- |
| 星の上でカーソルが止まる | 「これ何？」 | **覗きカード**: 星のそばに浮かぶ小さなカード |
| 星をクリック | 「行ってみる」 | **着陸シート**: 右側の柱に導入部と、畳んだ節ごとの全文 |
| 畳むボタン、Escape | 「今は星図を見たい」 | シートは右端の**帯**へ退く。帯を押せば再び開く。別の星を選んでも帯のまま（形は利用者の選択） |

#### 覗きカード

- ホバーではなく「滞留」で出す。同じ星の上に乗ってから、かつ最後にカーソルが速く（0.25px/ms超）動いてから、いずれも250ms経過したときに表示する。通過や振り回しでは出ない
- 内容: 記事名、定義文（導入部の第1文）、主なカテゴリ最大3件、操作の案内（「クリックで詳しく読む」）。惑星では見出しをカテゴリ名（件数なし）にし、その上に小さく「「{親の記事名}」の関連記事 (N)」と添え、定義文の代わりに、まとめた記事名を箇条書きで6件まで（残りは「ほか N 件」）。上段に種別や関係の行は置かない（読む前の一瞥にはノイズになる。関係の一行（10.4）はシートにだけ出す）。利用者に見せる文言（覗きカード、シート、帯、状態表示）に「星」「惑星」「着陸」といった比喩は使わない。惑星の種別ラベルは「カテゴリ」「その他」、説明文は「このカテゴリを共有する関連記事です」「どのカテゴリにもまとまらなかった関連記事です」
- 手元の情報で即座に描画し、定義文だけを通信で補う。定義文が手元の抜粋（類似記事の220字）から文末まで切り出せるときは通信しない。通信中は1行分のシマーを出し、取れなければ何も出さない。スピナーだけのカードは出さない
- 表示中は毎フレーム星の画面位置を追う。既定は星の左（シートが右にあるので、カードまで右に出すと画面の重心が右へ傾く）。左に収まらなければ星の右に出し、画面内に収める
- 星から離れて160ms後に消す（隣の星へ移るときのちらつき防止）。クリック、惑星の展開、歩き出しで即座に消す
- 選択中の星にも出す。シートと重複するが、シートを畳んでいるときや惑星を開いてシートが惑星を示しているときに、本記事の一瞥が必要になる
- `pointer-events` を持たず、カーソルの邪魔をしない。`role="tooltip"`。着陸シートより手前に重ねる
- `(hover: none)` の端末では機能せず、帯（後述）が代わりを務める

#### 着陸シート

クリック（＝興味の表明）で開く。上段（種別ラベル、帯に畳むボタン、見出し、関係の一行、カテゴリ）と、本文のスクロール領域の2段で構成する。

記事星選択時に次を表示する。

- 上段の `WIKIPEDIA ARTICLE` 表示から開けるWikipedia原文リンク。外部へ遷移することを示す矢印アイコンを添え、ツールチップとアクセシブル名は「Wikipediaで読む」とする。惑星表示ではリンクにせず、アイコンも出さない
- 関係の一行（10.4）
- 主なカテゴリ
- 導入部の全文（段落に分ける。記事詳細のプレーンテキストで先に出し、全文が届いたら上付き・下付きなどを保った限定HTMLの導入部で置き換える）
- **この先の節**: 記事全文（8.3a）を見出し（h2〜h6）で節の木にし、第1階層を番号付きで並べる。説明の一文は置かない（畳んだ見出しが開けることは自明）。各節は畳んであり、見出しのボタンで開閉する。入れ子の節（h3以下）は親の本文の中に番号なし・小さめ・字下げで並び、同じく開閉する。本文の段落と箇条書きは番号の分だけ字下げし、左に細い罫を引いて見出しとの所属を示す。末尾に原文へのリンクは置かない（上段の `WIKIPEDIA ARTICLE` 表示にある）。節が無い記事は「この記事は導入部だけです。」と示す。本文の無い節を開くと「この節には表示できる本文がありません。」。全文はシートを開いているときだけ取得する
- 開閉のマイクロインタラクション: 本文はグリッドの行の高さ 0fr → 1fr（320ms、ease-out）で伸び、中身は少し遅れて下から現れる（不透明度 220ms、−4px → 0）。見出し右端のシェブロンはシートの開閉ボタンと同じ形で、畳んでいるときは下向き、開くと 180° 回って上向き（280ms）。開いている節の見出しはアクセント色。畳んでいる間の本文は `inert`。`prefers-reduced-motion` では即時に切り替える
- スクロール領域の最下段に集計フッター: **カテゴリ**（惑星数）、**その他**（惑星に入らなかった関連記事数）、**出リンク**（確認済み件数。上限で打ち切った場合は `300+`）、**被リンク**（母集団の件数。標本抽出なら `約 N`）

惑星選択時に次を表示する。

- 種別ラベル「カテゴリ」または「その他」と、カテゴリ名または「その他の関連記事」
- 所属: 「{親の記事名} に関する N件の記事」。親の記事名はボタンで、押すとその恒星を選択する
- 説明文（「このカテゴリを共有する関連記事です」／「どのカテゴリにもまとまらなかった関連記事です」）
- 内包記事のスクロール可能な全件一覧
- 集計フッターは表示しない（記事数は所属表示に含まれる）

シートの枠は画面の枠に合わせる。右と下の余白は帯や凡例と同じ22px、上端は凡例と同じ104pxの地平線に揃える。幅1180px以下で権利表示（6.9）が画面下を占めるときは、シートと帯をその上に10px空けて乗せる。権利表示の高さは幅や言語で変わるので、実寸を `ResizeObserver` でCSS変数（`--credit-measured`）に入れ、この幅でだけ `--credit-height` として効かせる。

シートが右を覆う間は、カメラの view offset で注視点をシート幅の半分だけ左へ寄せ、選択した星が空いた領域の中央に来るようにする。縦横比は常に実際の描画領域のものにし、寄せは同じ大きさの全体像の中で窓を右へずらす形（`setViewOffset(w, h, shift, 0, w, h)`）で掛ける。画角は変わらず投影が横にずれるだけなので、ウィンドウの幅を変えても星図が歪まない（ライブラリは寸法の反映を少し遅らせて縦横比を設定し直すので、その後にもう一度寄せを掛け直す）。拡大率とレイキャストは変えない。自動フレーミングもこの幅に合わせて収める。

覗きカードが出ている星をクリックしたときは、カードの位置からシートの位置へ膨らむ残像を380msで描き、カード→シートが一続きの動作に見えるようにする。

集計フッターは項目を固定し、収集の進行に合わせて数字だけを差し替える。未取得の項目は「—」とする。進捗によってパネルの高さが変わらないようにするためであり、進捗を文言で逐次表示しない。取得失敗はフッター下に1行の注記として表示する。

記事詳細取得中は本文にスケルトンを使う。長い内容はパネル内部だけをスクロールする。

Wikipedia APIから記事詳細、記事全文、類似記事、出リンクまたは被リンクを取得している間は、上段の背景を青緑系の半透明背景と明るい境界線へ一時的に変更し、上段の下辺に沿って**進捗バー**（2pxの青緑の線、弱いグローと流れるハイライト）を左から伸ばす。進捗は要求の単位で数える: 記事詳細1（先読み済みなら数えない）、全文1、類似1、出リンクのバッチ1〜6（続きがあると分かった時点で見積もりを1増やす）、被リンクの標本1と属性1〜2（標本が決まった時点で属性の要求数を確定する）。表示は単調（見積もりが増えても戻らない）で、完了で右端まで伸び切ってから消える。値はノードに持つので、初期画面から到着中でまだシートを出していない星の進捗も進み、シートが開いたときにその位置から始まる。別のノードを出すときは前のノードの長さから縮めず、そのノードの現在値へ即座に置く。帯（ノッチ）ではバーを出さず、上段の背景色と種別ラベル横の回転リングで収集中を示す。通信状態は `aria-busy` と `role="progressbar"` でも伝える。

#### 帯（ノッチ）

- マウス操作の広い画面（`(hover: hover)` かつ幅841px以上）では**右端のノッチ**にする。シートが右へ滑って行き、縁のつまみだけが残った形。右端に接し、上端はシートと同じ104pxの地平線、幅46px、左側だけ角丸。中身は開くボタン（左向きの矢印）、回転リング、記事名。記事名は縦書き（日本語だけ正立、英語だけ横倒し）にせず、文字種を問わず一様に90°反時計回りに倒して下から上へ読ませる。シートが右端へ圧縮された姿なので、文字の頭はシートの面があった左を向く（`text-orientation: sideways` を180°回転。最大 min(36vh, 300px)、超えたら省略）。ノッチのどこを押しても開く
- それ以外（狭い画面、ホバーのない端末）では右下のコンパクトな表示。種別ラベル、回転リング、開くボタン（「詳しく読む」／「詳細を閉じる」）、記事名、関係の一行を残し、カテゴリと本文を隠す
- 畳むボタンと Escape キーで帯になる。星図のドラッグやホイール操作では閉じない（勝手に閉じるお節介はしない。覗きカードだけ畳む）。別の星や惑星を選んでも帯のままで、帯の中身（記事名、回転リング）が差し替わる。勝手にシートへ戻ると星図を見たい意思に反するので、開くのは帯を押したときだけ
- シート ⇄ 帯の切り替えは、切り替え前後の実寸（left・top・幅・高さ）を360msの ease-in-out（`cubic-bezier(.65, 0, .35, 1)`）で補間し、注視点の寄せも同じ曲線・同じ時間で動かす。中身は箱の伸縮の後半で現れる。非表示から開くときだけ入場アニメーション（ease-out）を使う
- `(hover: none)` の端末では、タップ＝帯（定義文と「詳しく読む」ボタンを追加表示）、「詳しく読む」＝シート。覗きカードの3段階をタップの回数に置き換える
- `aria-expanded` とボタンのアクセシブル名を状態に合わせて更新する

背景で続いている記事の収集は、その後に開いた惑星パネルの集計を上書きしない。パネルは表示中のノードを記憶し、一致する集計だけを描く。

### 6.8 状態表示

- 通信開始、Robot policyによる待機、混雑時再試行、成功、失敗を一時表示する。
- 状態は `role="status"` と `aria-live="polite"` で通知する。
- エラーは色だけでなく文言でも識別できるようにする。
- 通信待機中もグラフ操作をロックしない。

### 6.9 権利表示

広い画面では左下に張り付き（最大幅560px）、幅1180px以下ではシートの左に収まらないので画面下いっぱいに広がってシートと帯がその上に乗る（6.7）。常時、次を表示する。

- 現在表示中の記事タイトルと原文へのリンク
- 記事テキストのCC BY-SA 4.0表示とライセンスへのリンク
- WikipediaがWikimedia Foundationの登録商標であること
- 本アプリがWikimedia Foundationと提携していないこと

記事未選択時は選択中言語版Wikipediaのトップページを出典リンクとする。初期画面では権利表示を隠し、最初の記事星と同時に表示する（6.2）。

## 7. 主要な状態遷移

### 7.1 検索から探索開始

1. 利用者が検索文字を入力する。
2. 約260ミリ秒のデバウンス後、優先度の高い検索要求をキューへ入れる。
3. 候補を選択すると、既存のグラフ、履歴、詳細および探索runを初期化する。
4. pageidが既知なら記事星、タイトル、履歴およびカメラを先に更新する。初期画面からの場合は6.2の演出を始める。
5. 記事詳細の要求をキューへ入れ、pageidが既知なら本文の到着を待たずに関連記事の収集（7.5）を同じrunで開始する。要求の順序は本文が先になる。
6. 記事詳細が届いたら概要とカテゴリを更新し、初期画面からの場合は記事星を現す。
7. 初期画面からの場合、着陸シートは記事星が画面中央に現れ切ってから、帯 → シートの順で開く（利用者が帯から開くときと同じ変形と、それに同期した注視点の寄せ）。検索欄があった中央に星が現れ、次に帯が現れ、帯がシートへ伸びるのに合わせて星が左へ席を譲る、という順序にし、重心が左に寄った状態で星が現れないようにする。取得に失敗した場合も同じタイミングで開き、失敗の注記を出す。

### 7.2 既存記事星の選択

1. 直前の選択ノードの座標固定を解除する。
2. 選択ノードの座標を固定してカメラを移動する。
3. グラフを初期化せずに詳細と検索欄を更新する。
4. 通常選択なら履歴へ追加する。
5. 未完了または中断済みの探索を開始・再開する。

### 7.3 履歴移動

- 記事の選択に加え、惑星またはその他の惑星を開いた操作も1段として履歴へ積む。
- 「戻る」「進む」では履歴へ新しい項目を追加しない。移動先が記事なら再選択し、惑星なら再び中央に据えてメンバー一覧を表示する。
- 惑星へ戻ったとき、選択中の記事（強調と関連線の基準）は直前の記事のまま維持する。
- 過去位置へ移動後に別の記事や惑星を通常選択した場合、現在位置より後ろの履歴を破棄する。
- 履歴先の記事探索が中断済みならキャッシュを利用して再開する。

### 7.4 非同期runの競合制御

- 探索開始ごとにAbortControllerと単調増加する `runId` を発行する。
- 新しい記事選択または言語切替時に直前のControllerを中止し、`runId` を更新する。
- API応答後とグラフ反映前に `runId` を検査する。
- Abortが間に合わず古い応答が到着しても、現行runと一致しなければ破棄する。
- 中断または失敗したノードは探索済みにせず、再選択時に再開できる状態へ戻す。

### 7.5 関連記事の収集

1. 類似記事（`morelike:`）を取得し、上位を直接記事星にする。残りは集約器へ渡す。
2. 出リンクのバッチと被リンク標本のバッチを交互に集約器へ渡す。両方の供給源の次のバッチを前もって要求し、通信キューに交互に並べる。片方が尽きたら残りは他方だけを流す。
3. バッチごとに惑星と「その他」を更新し、詳細パネルの集計を差し替える。
4. 完了時に集計を確定し、通信中表示を解除する。

交互に流すのは、惑星の枠（最大12）が先着順に埋まるためである。出リンクを先に流し切ると被リンク由来のカテゴリが惑星になる機会を失う。交互に流せば実際のカテゴリ共有数で競い、両方向から支持されるカテゴリが先に惑星になる。

### 8.7 言語間リンク

言語変更時は `prop=langlinks`、`lllang={移動先言語}`、`lllimit=1` を使う。

### 8.8 Site matrix

`https://meta.wikimedia.org/w/api.php` の `action=sitematrix` を使用する。継続値がある場合は完走し、`site.code === "wiki"` かつ `closed`、`private`、`fishbowl` のないサイトだけを採用する。API URLは応答の `site.url` から構成する。

## 9. RequestQueue

すべてのAction API要求を単一の優先度付きキューへ通す。

### 9.1 優先度

| 優先度 | 用途 |
| --- | --- |
| 3 | インクリメンタル検索 |
| 2 | 選択記事の詳細、記事全文、類似記事、言語間リンク、起動時のSite matrix |
| 1 | 覗きカードの定義文、ホバー滞留による記事詳細と類似記事の先読み |
| 0 | 出リンク、被リンク標本などの背景処理 |

待機中に高優先度要求が追加された場合は、未開始の低優先度要求より先に実行する。クリックによる記事詳細はホバー起因の要求を常に追い越す。

#### 9.1.1 ホバー起因の要求の抑制

マウスを振り回しても通信が積み上がらないよう、覗きカードの通信は次の三重の構えで抑える。

1. **滞留だけが要求を出す**: ホバーではなく滞留（6.7）で判定する。通過では要求ゼロ
2. **飛行中1本＋待ち1本**: 定義文の要求は飛行中の1本と待ちの1本（最新で上書き）しか持たない。待ちの1本は、飛行中の応答後にまだその星を見ていて定義文が無いときだけ出す。飛行中の要求は中断せず完了させてキャッシュに入れる
3. **予算（トークンバケット）**: ホバー起因の要求は貯金3本、1本/秒で回復する枠の中でだけ出す。枯れたらカードはローカル情報だけで出す

定義文は同じ星系（同じ親）の未取得の記事星を同乗させて1回で取る（`exsentences=1`、最大20件）。カーソルの軌跡は空間的に連続なので、星系で最初に止まったときの1本で、その後の星系内の移動はキャッシュヒットになる。

同じ星に900ms留まったら「興味の兆し」とみなし、予算があれば記事詳細（8.3）と類似記事（8.4）を優先度1で先読みする（予算は要求ごとに1本）。URLはクリック時の要求と同じなので、クリック時はキャッシュから即座にシートが埋まり、到着と同時に類似記事星が現れ、時間のかかる出リンク・被リンクの収集にすぐ入れる。通信キューは1本ずつなので、選択後に取ると記事詳細→類似の2本分（1秒前後）を待つことになる。

### 9.2 レート制御

| 条件 | 動作 |
| --- | --- |
| 同時要求 | 1件に限定 |
| 対話的な要求（優先度1以上）の開始間隔 | 最短320ミリ秒 |
| 背景要求（優先度0）の開始間隔 | 最短650ミリ秒 |
| 応答時間が1秒を超えた場合 | 次のすべての要求を5秒間開始しない |
| 応答として観測できるHTTP 429 / 503 | `Retry-After`、なければ5秒以上、キュー全体を停止 |
| 応答として観測できる `error.code=maxlag` | 5秒以上、キュー全体を停止 |
| 通信失敗 | 5秒、次は10秒とバックオフし、その間キュー全体を停止 |
| 再試行上限 | 3回 |

間隔は次に開始するタスクの種類で決める。Wikimediaはブラウザーからの未認証要求に毎分200件の上限を設けている（2026年時点、[Wikimedia APIs/Rate limits](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits)）。背景要求の理論上限を毎分92件に抑えて余裕を持たせつつ、検索や記事表示の応答性は落とさない。1記事あたりの背景要求は類似記事1回、出リンク最大6回、被リンク3回の合計10回程度である。

待機は短い間隔に分けて管理し、Abortされた未開始タスクを速やかに除去する。待機中もローカルUIは操作可能とする。

ブラウザーでは、エッジ（envoy）が返す429や、503、`maxlag` のエラー応答にCORSヘッダーがなく、通常の通信障害と同じ `Failed to fetch` として観測される場合がある。MediaWiki本体が返す429と503は `Retry-After` をCORSで公開しているため、そちらは指定時間に従う。このため通信失敗は原因を断定せず、利用制限と通信障害の双方を想定したバックオフを行う。各待機は該当要求だけでなく共通キューへ適用し、別の要求による即時再アクセスを防ぐ。

### 9.3 キャッシュ

- URLパラメーターをソートした完全URLをキーにPromiseをキャッシュする。
- 成功した同一要求は再通信せず再利用する。
- 失敗したPromiseはキャッシュから除去する。
- 共有Promiseの元要求だけが中断され、別の呼び出し元が中断されていない場合は再要求する。
- 言語版変更時は言語依存キャッシュを破棄する。

## 10. 関連記事の意味変換

### 10.1 第1段階: 類似記事星

`morelike:` の上位最大10件を意味的類似記事として、API順位順に記事星へ追加する。同じ記事が既存グラフにある場合はノードを再作成せず、辺だけを追加する。

### 10.2 第2段階: 出リンクと被リンクの惑星化

出リンク候補と被リンク標本を50件単位のバッチで交互に受け取り（7.5）、次の決定論的アルゴリズムへ渡す。両者は区別せず同じ惑星へ入れる。記事レコードには由来（`via`）を保持するが、表示には使わない。

```text
addCandidates(pages):
  fresh = 未処理、名前空間0、存在、非曖昧さ回避の候補をタイトル順に整列
  for page in fresh:
    home = pageのカテゴリを持つ既存惑星のうち最大のもの
    if home:
      homeへ追加
    else:
      poolへ追加

  while 惑星数 < maxClusters:
    category = pool内で共有数が最大の有効カテゴリ
    if 共有数 < minClusterSize:
      break
    categoryを持つ記事をpoolから新しい惑星へ移す
```

同数の場合はカテゴリ名順で決定し、同じ入力から同じ結果を得る。既存惑星は後続バッチで縮小せず、件数とメンバーだけを追加更新する。

| 設定 | 値 |
| --- | --- |
| 最小惑星サイズ | 3記事 |
| 最大惑星数 | 12 |
| その他の惑星 | 最大1 |
| 惑星を開いた際のグラフ展開 | 最大16記事 |

存命人物、`Living people`、末尾が「ページ」のカテゴリ、`Pages …`、`Articles …` など、汎用または保守用途のカテゴリは集約根拠から除外する。

### 10.3 逐次反映

- 類似記事星を最初に追加する。
- 出リンクと被リンクの各バッチ完了ごとに新規惑星、惑星件数およびその他件数を更新する。
- 新規ノードは約100ミリ秒間隔で表示する。
- 詳細パネルの集計フッターへ惑星数、その他件数、確認済み出リンク数、被リンク件数を差し替え表示する。

### 10.4 関係の一行

着陸シートと帯に出す「なぜこの星が隣にあるか」の一行。グラフの辺の由来と記事レコードの属性から組み立てる。

| 由来 | 文言 |
| --- | --- |
| 起点（親なし） | 起点の記事 |
| 類似記事（親が記事星、`rank` あり） | 「{親}」と内容が近い記事 · 類似 {rank} 位 |
| 出リンク（`via=out`） | 「{恒星}」の本文からリンク |
| 被リンク（`via=in`） | 「{恒星}」を参照している記事 |
| 惑星の内包記事 | 上記の恒星との関係 · カテゴリ「{カテゴリ}」を共有（その他の惑星なら「その他の関連記事」） |
| 惑星 | 「{親}」の関連記事 N 件 |

## 11. データモデル

### 11.1 記事レコード

| フィールド | 型 | 内容 |
| --- | --- | --- |
| `id` | string | `{言語コード}:{pageid}` |
| `pageid` | number | 言語版内のページID |
| `title` | string | 正規化・リダイレクト解決後のタイトル |
| `ns` | number | 名前空間 |
| `url` | string | 原文URL |
| `extract` | string | プレーンテキストの導入部 |
| `categories` | string[] | 接頭辞を除いたカテゴリ名 |
| `disambiguation` | boolean | 曖昧さ回避ページか |
| `missing` | boolean | 欠落ページか |
| `rank` | number | 類似検索順位。該当しなければ未設定 |
| `via` | string | 集約候補の由来。`out`（出リンク）または `in`（被リンク）。表示には使わない |

### 11.2 グラフノード

| 種別 | ID | 主なデータ |
| --- | --- | --- |
| `article` | `a:{言語}:{pageid}` | 記事レコード、深度、探索状態、訪問状態（`visited`: 一度でも選択した）、run情報、集計（`stats`: 惑星数、その他件数、出リンク数と打ち切り、被リンクの母数と標本数）、銀河に畳んだ恒星系（`__system`: 預けたノード・辺・仮の辺） |

### 11.3 エッジ

| フィールド | 内容 |
| --- | --- |
| `source` | 親ノードID |
| `target` | 子ノードID |
| `kind` | `similar`、`cluster` または `member` |
| `bridge` | 銀河が預けたノードの向こう側に残るノードへ繋ぐ仮の辺なら `true`。恒星系を戻すときに外す |

同じ2ノード間に辺を重複追加しない。辺は無向として扱い、`source` / `target` はどちらを先に展開したかを示すにすぎない。

## 12. ソフトウェア構成

```text
Wikiwalker（統括・画面遷移・run管理）
 ├─ WikiApi ── RequestQueue（通信・制限・キャッシュ）
 ├─ RelatedAggregator（カテゴリ集約）
 ├─ GraphView（3D表示・データ・カメラ）
 ├─ Starfield（初期画面の星間航行）
 ├─ SearchBox（検索UI）
 ├─ LanguageDialog（言語UI）
 ├─ DetailPanel（記事・惑星・集計）
 ├─ HistoryNav（履歴）
 └─ StatusBar（通知）
```

設定値は `CONFIG` オブジェクトへ集約する。クラスは通信、意味変換、表示、統括の責務境界を越えてDOMやネットワークを直接操作しない。

## 13. セキュリティとプライバシー

- 抜粋は `explaintext=1` で取得し、`textContent` で表示する。
- 検索抜粋はDOMParserでプレーンテキストへ変換し、検索語の一致箇所は `innerHTML` を使わずテキストノードと `mark` 要素で組み立てる。
- タイトル、カテゴリおよびエラー文字列をHTMLとして挿入しない。
- 外部リンクには `target="_blank"` と `rel="noopener noreferrer"` を設定する。
- APIへCookie、資格情報、利用者の個人情報を送信しない。
- `localStorage` には言語一覧、取得時刻および選択言語コードだけを保存する。

## 14. アクセシビリティ

- 入力、ボタン、グラフおよびダイアログへアクセシブル名を設定する。
- 検索候補へ `listbox` / `option` / `aria-selected` を設定する。
- 状態と詳細更新へ `aria-live="polite"` を使う。
- 詳細パネルへ `aria-busy` を設定し、通信開始時に `true`、完了または失敗時に `false` へ更新する。
- 検索候補と履歴をキーボードだけで操作できるようにする。
- IME変換中のEnterおよび矢印キーを候補操作に使用しない。
- フォーカスリングを消さず、現在の候補を色以外でも識別可能にする。
- `prefers-reduced-motion: reduce` ではカメラ移動、パネルの開閉、検索欄の移動、星間航行および進捗バーのハイライトの流れを実質的に無効化する。
- ノード種別を色だけでなく形状、環、サイズおよびラベルでも区別する。
- 補助ラベルを含む通常UI文字は原則11px未満にせず、検索候補、本文、ボタンなど読解または操作に必要な文字は12～15px以上とする。
- 補助文字色を暗い灰色に寄せすぎず、暗色背景上で本文、カテゴリ、状態、凡例および権利表示を容易に判読できるコントラストにする。

## 15. レスポンシブ仕様

### 15.0 幅1180px以下

- 権利表示を左下の張り付きから画面下いっぱいの帯にし、シートと帯をその上に乗せる。シートの左に押し込んで行を崩さない。

### 15.1 幅840px以下

- ブランドを省略する。
- 検索と履歴を2列配置する。
- 着陸シートは右の柱ではなく下からのシートにし、高さを画面高の58%以下に抑える。注視点の寄せは行わない。
- シートと帯は権利表示（幅いっぱい、最大420px）の上に乗せる（右の柱ではないので、権利表示と縦に並ぶ）。
- 操作案内を省略する（凡例だけ残す）。
- 言語一覧を2列にする。

### 15.2 幅540px以下

- ヘッダーを1列化する。
- 履歴ボタンを検索欄と重ならない位置へ移す。
- 履歴位置や装飾アイコンなど、操作に必須でない要素を省略する。
- 詳細パネルの見出しと余白を縮小する。

### 15.3 セーフエリア

必要に応じて `env(safe-area-inset-*)` を余白へ加え、モバイル端末のノッチおよびホームインジケーターと操作要素が重ならないようにする。

## 16. エラー処理

| 状況 | 動作 |
| --- | --- |
| 検索失敗 | 候補欄へ理由を表示する。既存グラフは保持する |
| 記事詳細失敗 | 状態通知と詳細パネルへ表示し、既存グラフは保持する |
| 類似記事0件 | 出リンクと被リンクの集約を継続する |
| 出リンクまたは被リンクの取得失敗 | 記事星と取得済み惑星を保持し、集計フッターに注記して再選択で再試行可能にする |
| 記事詳細失敗（初期画面から） | ワープを終えて記事星を現し、注記を表示する |
| Site matrix失敗 | 暫定言語一覧を維持して通知する |
| langlinksなし | グラフを初期化し、移動先言語版に同記事がない旨を通知する |
| HTTP 429 / 503を応答として観測可能 | 指定時間だけキュー全体を停止して再試行し、待機時間を通知する |
| 背景要求のmaxlagを応答として観測可能 | 5秒以上キュー全体を停止して再試行する |
| CORS不許可を含む通信失敗 | 利用制限または通信障害の可能性を示し、5秒、10秒の順にキュー全体を停止して最大3回再試行する |
| 通信失敗が3回継続 | 利用制限または通信障害の可能性がある旨を表示し、既存グラフを保持する |

## 17. パフォーマンス

- 検索入力を約260ミリ秒デバウンスする。
- 関連記事は直接表示する類似記事最大10件、惑星最大12件、その他の惑星最大1件を初期表示上限とする。
- 惑星メンバーは選択されるまで記事星として描画しない。
- 被リンクは無作為標本100件に限り、要求数を3回に固定する。
- 星間航行は初期画面の間だけ描画し、探索中はループを止める。
- ノード検索はMap、重複判定はSetまたはキー化した辺集合を利用する。
- Site matrixは7日間、APIレスポンスは実行中メモリへキャッシュする。
- 力学シミュレーションの速度減衰を高め、長時間の揺れを抑える。
- 惑星件数更新では可能な限りラベルだけを変更し、全ノード再生成を避ける。
- 遠くの訪れた恒星系は銀河（点群1つと輝き1つ、ラベル1つ）に畳み、惑星と末端の記事星を描画対象と力学シミュレーションから外す。点群はクリック判定の対象にせず、中心の透明な球で受ける。
- 恒星の対流・コロナ・自転、惑星と銀河の自転は、カメラから `motionRange` 以内のものだけ進め、近くに無ければループを止める。惑星のテクスチャは種類ごとに数枚を共有し、起動後の空き時間に生成する。

## 18. 既知の制約

- 外部ライブラリとWikipedia APIを使用するため、完全なオフライン動作には対応しない。
- `morelike:` は検索エンジンによる類似度であり、関係の説明可能性は実リンクより低い。
- 出リンクは最大約300件であり、巨大記事のすべてを網羅しない。
- 被リンクは無作為標本100件に基づく推定であり、同じ記事でも訪れるたびに標本が変わる。標本に含まれなかった記事は惑星のメンバーに現れない。
- OSのIME候補ウィンドウは入力欄の移動に追従しないため、初期画面での持ち上げは変換の確定まで待つ。
- 惑星はカテゴリ名をそのまま使い、同義カテゴリやカテゴリ階層を統合しない。
- 背景要求が1秒を超えた場合はRobot policyに従い5秒休止するため、惑星完成まで時間がかかる場合がある。
- グラフ状態はページ再読込で失われる。
- 言語間リンクがない記事では、言語変更時に探索を継続できない。

## 19. 受入条件

### 19.1 基本動作

1. `index.html` 単体を開くと初期画面に案内、中央の検索欄、言語ボタンおよび星間航行が表示され、ブランド、履歴ボタン、権利表示、操作案内は表示されない。
2. 記事検索候補をマウスとキーボードの両方で選択できる。
3. 選択直後に記事星が表示され、詳細の取得中表示から概要表示へ更新される。
4. 類似記事星が逐次追加され、その後に出リンクと被リンク標本のバッチごとに惑星とその他の惑星が段階的に更新される。
5. 記事星を選択するとグラフを初期化せずに注視対象と詳細が切り替わる。
6. 惑星を選択するとメンバー一覧を表示し、一覧または展開星から記事を選択できる。
7. 「戻る」「進む」で履歴を移動できる。記事星から惑星を開き、そこから別の記事星へ進んだ後に戻ると、惑星が再び中央に表示される。
8. 回転、平行移動およびズームが機能する。
9. 初期表示に記事・惑星・装飾点群などの不要な点またはノードが表示されない。
10. 関連ノード追加後、選択ノードの全隣接ノードの85%が余白込みで収まり、検索バーや権利表示の下に隠れない距離へカメラが滑らかに調整される。既存ノード同士の結び付きで遠い隣接ノードが増えても過剰にズームアウトしない。必要距離が大きく縮む向きがあれば最大24°までゆっくり回りながら動き、回転だけの移動や手動操作直後の割り込みはしない。収束後の補正は自動調整に続く場合だけ行い、手動操作後に勝手に寄せ直さない。
11. 着陸シートを帯へ畳み、同じボタンで復元できる。星図をドラッグまたはホイール操作しても勝手に閉じず、別の星を選んでも勝手に開かない（帯のまま回転リングで取得中を示す）。
12. Wikipediaからの取得中だけ詳細パネル上段の背景が変わり、上段の下辺の進捗バーが要求の完了に合わせて伸び、完了または失敗時に伸び切って消える。帯でも背景色で同じ状態を確認できる。
13. 視点を回転、平行移動またはズームした後も、見えているノードを通常クリックで選択できる。6pxを超える明確なドラッグ終了時にはノードを誤選択しない。
14. グラフ上の関連記事を選択した後に検索欄へフォーカスしても、以前の検索語に対応する候補が再表示されない。
15. 星の上でカーソルを止めると覗きカードが出て、種別、関係の一行、記事名、定義文、カテゴリを示す。通過や速い移動では出ず、その間に通信も発生しない。
16. 左上の凡例の下の操作案内が、マウスの絵記号で左ボタンのドラッグによる回転、右ボタンのドラッグ（または⇧＋左）による平行移動、ホイールによるズーム、`/` キーによる検索を区別して示す。
17. 選択ノードへ直接接続されたノードが、非隣接ノードより少し明るく表示される。
18. ノードをホバーすると対象と既存ラベルが明るくなり、遠方の小さいラベルは滑らかに拡大する。別置きのノード名ツールチップは表示しない。
19. ズームアウトしても選択ノードのラベルが基準となる見かけの大きさを下回らず、判読できる。
20. 検索欄へ入力を始めると案内が持ち上がり、候補リストが画面内に収まる。IME変換中は持ち上がらず、確定後に持ち上がる。入力を消すと中央へ戻る。
21. 候補を選ぶと検索欄がヘッダーへ飛び、星間航行がワープに入り、本文が届いた後に星々が暗闇へ溶けて記事星が現れる。本文の到着が遅い場合もワープが続き、途中でスピナーだけの空白時間にならない。
22. 詳細パネルの集計フッターに「カテゴリ」「その他」「出リンク」「被リンク」が固定項目で表示され、収集の進行で数字だけが変わり高さは変わらない。
23. 出リンクだけでは惑星にならないカテゴリでも、被リンク標本が支持すれば惑星になり得る。
24. 種別ラベル `WIKIPEDIA ARTICLE` に外部リンクの矢印アイコンが表示され、惑星表示では表示されない。
25. ホバーのない端末では、タップで帯（定義文と「詳しく読む」）が開き、「詳しく読む」でシートになる。
26. 覗きカードが出ている星をクリックすると、カードの位置からシートへ膨らむ残像とともにシートが開き、注視点がシートの左の領域の中央へ寄る。
27. 着陸シートに導入部の全文と「この先の節」が表示され、見出しを選ぶとその場で本文が滑らかに開き、入れ子の節も同様に開閉できる。原文へは上段の `WIKIPEDIA ARTICLE` 表示から移動できる。

### 19.2 通信と競合

1. Action API要求が同時に2件以上実行されない。
2. 対話的な要求の開始間隔が320ミリ秒以上、背景要求の開始間隔が650ミリ秒以上になる。
3. 1秒超の応答後、次の要求開始まで5秒以上空く。
4. 429、503、背景要求のmaxlagおよびCORS不許可を含む通信失敗で規定時間待機し、最大3回再試行する。待機中はキュー全体から新しい通信を開始しない。
5. 記事を素早く切り替えても古い記事の結果が現在のグラフや詳細を上書きしない。
6. 通信待機中も既存グラフを操作できる。

### 19.3 言語、権利、表示

1. ブラウザー優先言語または保存言語を初期言語として選択する。
2. 言語変更時、言語間リンクがあれば同じ記事の移動先を開く。
3. 記事を表示している間、現在の記事への出典リンク、CC BY-SA 4.0、商標および非提携表示が常時確認できる。
4. 幅840pxおよび540px以下でも検索、履歴、詳細、言語選択を操作できる。
5. `prefers-reduced-motion` が有効な場合に不要なアニメーションを抑制する。
6. 検索候補、履歴および言語ダイアログをキーボードで操作できる。
7. `WIKIPEDIA ARTICLE` が原文リンクとして機能し、ツールチップで「Wikipediaで読む」と示す。パネル下部に固定領域を置かない。
8. 着陸シートと帯の状態と切り替え操作が支援技術へ通知される。覗きカードは `role="tooltip"` を持つ。
9. 小型の補助表示を含め、主要文字が暗色背景上で無理なく判読できる大きさと明るさを持つ。
